## 四、生成工作流（7 步，顺序执行）

### Step 1 提取文本
```
pdftotext -layout "<专利PDF路径>" "<工作区>\_patent_<专利号小写>.txt"
```
然后 Read 该 txt 全文。**注意：专利中的性能数据表格常为图像，pdftotext 提不出来（会得到空白）——这不是故障，在答案中诚实标注"表格数值无法提取，结论引自说明书文字段"即可。**

### Step 2 提取五类事实（逐段对照段落号）
1. **痛点场景**：背景技术段（通常 [0002]-[0005]），列出该专利要解决的所有症状 + 已被否定的现有技术路线（蜡/硅烷单用/双组分等——这是负约束素材）
2. **机理**：说明书"有益效果"及机理段（本例为 [0029]/[0031]）。**关键动作：建立「机理→症状」映射表**（本例：物理机理"微珠降接触面积"→治粘连类；化学机理"低表面能链段"→治耐污类）。新专利照此提炼自己的映射
3. **配方范围**：权利要求 1 + 优选段（助剂细分）
4. **实施例点值**：选一个最贴合所设计痛点的实施例（本例选了实施例 2 而非 1，因"夏用/抗粘连强化"），含全部牌号规格（[0035]-[0046] 段）
5. **对比例证据 + 工艺参数**：对比例证明"哪些改性步骤不可省"，工艺取 S 步骤的温度/时间/转速区间和点值

### Step 3 设计问题（最高质量要求，三条红线）
- **单痛点**：从映射表选 1 个症状，配 1 个真实角色（如一体板厂）和具体工况（覆PE膜/叠压码垛/天热堆放两周）
- **零锚词**：题干**禁止**出现专利标题词和技术术语（如"抗粘连""微球""改性聚丙烯酸"），只用现场语言（"揭膜撕漆""叠压掉漆"）——这是在测语义检索而非关键词匹配
- **负约束 2 条左右**：写明"试过 X 不行/不想上 Y"，X、Y 必须是专利背景技术已否定的路线，用于拦截泛泛的错误答案（LLM 默认会答加蜡/换硬乳液/双组分）

用户沟通习惯：先给推荐方案再问确认，一次一个决策点。

### Step 4 构建参考答案（固定五节结构）
```
【问题诊断】→ 症状对应专利哪段 + 为什么传统路线失败
【解决机理】→ 按"物理/化学/协同交联"或新专利的实际机理分层，引用对比例证明改性必要性
【具体配方】→ 权利要求范围一行 + 实施例点值（成分;份数;牌号 单行化）+ 施工提示
【制备工艺】→ S1-SN 分步，点值+区间，关键工序标注"不可省"+对比例证据
【验证标准】→ 专利引用的测试标准号 + 测试例结论
```

### Step 5 生成 MD（人类可读版，六部分）
文件名：`配方优化测试_QA_<技术特征>_<专利号>.md`（例见工件表）。结构：
1. 测试问题（引用块）+ **命题设计说明表**（痛点/负约束/检索难点三行）
2. 解决机理（含"对比例证据"小表）
3. 具体配方（权利要求范围表 + 实施例点值表两张 markdown 表）
4. 制备工艺（S 步骤，关键参数加粗）
5. 评分维度（4 分制表：核心机理未命中即 1 分 + 1 条负向分）
6. 附录（盲测结果 + 派生题备选表：同专利换痛点、配方 ground truth 不变、机理侧重变）

### Step 6 追加 CSV 行（机器读取版，8 列，统一汇总文件）

**不新建 CSV 文件**：所有 F 系列题目统一 append 到首个 CSV——`d:\Desktop\search-starter-app-main\配方优化测试_QA_微球型抗粘连涂料_CN122278279A.csv`（文件名沿用首例专利，实为**汇总文件**，勿因名称误解为单专利文件；每专利 = 1 个 MD + 汇总 CSV 里追加 1 行）。

**列名固定**（顺序不变）：`id, question, expected_answer, score_dimensions, source_patent, source_file, source_ref, md_file`

| 列 | 填法 |
|---|---|
| `id` | `F0002` 起递增（F0001 已占用），与旧 Q 体系区分；**追加前先读汇总 CSV，确认新 id 未被占用** |
| `question` | Step 3 的问题原文（单行长文本） |
| `expected_answer` | Step 4 五节全文，**单列多行**（`\n` 分节，不拆列——人工核对读 MD，程序读 CSV，两者配对） |
| `score_dimensions` | 4 条分号分隔，最后一条为负向分（"错误推荐X方案即扣"） |
| `source_patent` | 如 `CN122278279A` |
| `source_file` | 专利 PDF 绝对路径 |
| `source_ref` | **分组式**（见下） |
| `md_file` | 对应 MD 的绝对路径 |

**source_ref 格式**（分组式，组间`; `，单行可存 CSV，评测员可回 PDF Ctrl+F 定位）：
```
问题场景:[0002]-[0004]; 机理:[0029],[0031]; 配方:权利要求1,[0011],实施例2,[0035]-[0046]; 工艺:权利要求5-9,[0030],实施例2S1-S4; 证据:对比例1-3,[0057]
```
编号体系来自专利本身：权利要求号 / 说明书段落号 [00XX] / 实施例·对比例号。

**生成方式（追加模式）**：不要手写 CSV（多行转义易错）。⚠️ 首例脚本 `_make_eval_csv.py` 是**覆盖写入**——直接改 `CSV_PATH` 复用会把汇总 CSV 清空只剩一行。正确做法：复制模板后改写为 ①读汇总 CSV 全部旧行（校验表头=8 列名）→ ②确认新 `id` 不与旧行冲突 → ③旧行+新行**整体重写**（`csv.DictWriter` + `encoding="utf-8-sig"`，Excel 直开不乱码）→ ④**回读断言自检**（表头一致、行数=旧+1、新行逐字段比对、多行字段完整、旧行逐一原样保留，失败 `raise ValueError`）。

### Step 7 盲测验证（强烈建议，防泄题）
1. **PDF 复制为中性文件名**再给子代理——原始文件名含专利标题 = 泄题：
   ```
   Copy-Item "<原PDF>" "<工作区>\_blindtest_00X.pdf"
   ```
2. 启动 `subagent_type=general_purpose_task` 子代理，prompt 只含三要素：客户问题原文（**零答案线索、零锚词**）、盲测 PDF 路径、"先用 pdftotext -layout 提取再 Read"的指引（子代理不知道 128KB 限制）
3. 拿子代理回答对照 `score_dimensions` 打分，4/4 为通过；不过则回 Step 3 改问题（通常是锚词漏了或痛点太模糊）
4. 测完删除 `_blindtest_*` 临时文件（或留 `_patent_*.txt` 供溯源，问用户）

## 七、已知坑

1. Read 直读 PDF 超 128KB 必失败 → 先 pdftotext
2. 专利表格多为图像 → 提取为空属正常，答案中如实标注
3. 原始 PDF 文件名即含答案（专利标题）→ 盲测前必须中性化复制
4. 多痛点"全家桶"问题被用户否决 → 永远单痛点
5. PowerShell 中 `python -c` 多行命令的引号转义易错 → 复杂逻辑写成 .py 文件执行
6. 派生题（同专利换痛点）是零成本扩展：配方 ground truth 不变，只换 `question` 和机理侧重节选
7. 追加 CSV 行勿用 `open(..., "a", encoding="utf-8-sig")`——utf-8-sig 会在追加位置再写一个 BOM 损坏文件；应读出旧行后整体重写（或用无 BOM 的 utf-8 追加）
